## 2. 曝光实验

固定增益 0 dB，像素格式 BayerRG8。实验室装甲板 LED 灯条损坏，未发光；画面整体极暗。

| 曝光 | 平均灰度 | 饱和像素比例 | 清晰度 Laplacian 方差 | YOLO 检测数 |
|---|---:|---:|---:|---:|
| 500 μs | 0.017 | 0.000 | 0.093 | 0 |
| 1000 μs | 0.235 | 0.000 | 0.592 | 0 |
| 3000 μs | 1.396 | 0.000 | 1.112 | 0 |

分析：

- 曝光从 500 μs 增加到 3000 μs，平均灰度从 0.017 增加到 1.396，约 82 倍，符合“曝光时间越长进光量越大”的规律；
- 但绝对亮度仍然极低，画面接近全黑，装甲板纹理和边缘不可见；
- YOLO 在三组图像上都没有检测到目标，说明短曝光 + 不发光装甲板导致有效信息不足；
- 由于目标未发光，本题无法在 500/1000/3000 μs 下获得可识别的正常画面。

## 3. 增益实验

固定曝光 1000 μs，像素格式 BayerRG8。

| 增益 | 平均灰度 | 饱和像素比例 | 清晰度 Laplacian 方差 | YOLO 检测数 |
|---|---:|---:|---:|---:|
| 0 dB | 0.211 | 0.000 | 0.539 | 0 |
| 6 dB | 0.771 | 0.000 | 1.205 | 0 |
| 12 dB | 1.813 | 0.000 | 2.200 | 0 |

分析：

- 增益从 0 dB 提高到 12 dB，平均灰度从 0.211 提高到 1.813，约 8.6 倍；
- 增益放大了信号，也同步放大了噪声；由于整体信号太弱，12 dB 下仍然没有可识别纹理；
- 没有出现饱和像素，说明当前瓶颈是进光量不足，而不是过曝；
- YOLO 在三组图像上都没有检测到目标。

## 4. 图像格式实验

固定曝光 1000 μs、增益 0 dB。

| 格式 | 处理方式 | FPS | CPU 占用 | 转换耗时 |
|---|---|---:|---:|---:|
| BayerRG8 | 相机原生 Bayer，OpenCV `cv2.cvtColor` 转 BGR | 70.4 | 161.9% | 0.62 ms |
| BGR8 | 相机原生 BGR8 | 70.4 | 46.9% | 0.61 ms |

分析：

- BayerRG8 每像素 1 字节，USB3 传输量小；但每帧需要 CPU 做 demosaic，CPU 占用明显更高；
- BGR8 每像素 3 字节，传输量约为 Bayer 的 3 倍；但相机内部完成转换，主机 CPU 占用显著降低；
- 两者采集 FPS 接近，说明本机 USB3 带宽和 CPU 都能支撑 1440×1080；如果分辨率或帧率更高，BGR8 的带宽压力会更明显；
- 本实验的“格式”严格区分了相机原生输出格式和程序转换后的格式。

## 5. 内存与异常处理

### 5.1 内存演示

`experiments/mat_memory_demo.py` 输出：

```text
start RSS: 56.9 MB
after 30 frames RSS: 99.9 MB
after clear + gc RSS: 99.0 MB
```

说明：Python/OpenCV 释放对象后 RSS 不一定立即下降，分配器会保留部分内存；这不代表泄漏，重复运行应关注 RSS 是否持续单调增长。

### 5.2 异常处理

`experiments/error_handling.py` 日志：

- 取流超时：`MV_CC_GetImageBuffer` 返回 `0x80000007`，程序捕获并记录；
- 非法 PixelFormat：`MV_CC_SetEnumValue` 返回 `0x80000101`，程序捕获并记录；
- `finally` 中执行 `StopGrabbing`、`CloseDevice`、`DestroyHandle`；
- 图像缓冲区在 `read_raw` 的 `finally` 中执行 `MV_CC_FreeImageBuffer`。

## 6. YOLO 识别结果

### 6.1 异常组：短曝光、不发光装甲板

| 曝光 | 增益 | 预处理 | 检测数 | 说明 |
|---|---:|---|---:|---|
| 500 μs | 0 dB | enhance | 0 | 画面几乎全黑 |
| 1000 μs | 0 dB | enhance | 0 | 画面几乎全黑 |
| 3000 μs | 0 dB | enhance | 0 | 画面几乎全黑 |

### 6.2 补偿组：长曝光 + 高增益 + 暗图增强

| 项目 | 值 |
|---|---|
| 曝光 | 30 ms |
| 增益 | 12 dB |
| 像素格式 | BayerRG8 |
| 预处理 | Gamma 0.7 + unsharp + bloom |
| 推理尺寸 | 960 |
| 检测结果 | B1 / R1，置信度 0.81 |
| 结果图 | `results/detection_success.jpg` |
| 演示视频 | `results/live_demo_enhance.mp4` |

分析：

- 装甲板 LED 损坏后，短曝光下目标与背景都接近黑色，YOLO 无法提取有效特征；
- 提高曝光到 30 ms、增益到 12 dB 后，画面进入可用亮度范围；
- Gamma 提亮暗部、unsharp 恢复边缘、bloom 模拟灯条高光，使 YOLO 重新检测到装甲板；
- 代价是帧率下降、运动拖影增加、噪声放大；因此该方案是设备受限下的补偿，不是正常发光条件下的最优方案。

## 7. 结论

1. 曝光和增益都能提高画面亮度，但增益同时放大噪声，且不能恢复已经丢失的纹理；
2. BayerRG8 省带宽但费 CPU，BGR8 省 CPU 但占带宽；
3. 装甲板 LED 损坏时，短曝光无法识别；长曝光 + 高增益 + 暗图增强可以恢复检测，但实时性和运动模糊会变差；
4. 正常作业条件下应优先保证光源和装甲板灯条工作，再在 500～3000 μs 范围内选择不过曝、拖影可接受的曝光。

## 8. 运动模糊补充实验（仿真）

由于实验室装甲板 LED 灯条损坏，且短曝光下无法获得真实运动目标的有效画面，本项使用**真实相机静态帧**加水平运动模糊核做补充分析。该结果明确是仿真，不替代老师要求的真实运动目标拍摄。

| 模糊长度 | 检测数 | 最高置信度 |
|---:|---:|---:|
| 1 px（原图） | 1 | 0.790 |
| 5 px | 1 | 0.678 |
| 11 px | 0 | 0 |
| 21 px | 0 | 0 |
| 31 px | 0 | 0 |

分析：

- 轻微模糊（5 px）时仍能检测，但置信度从 0.790 降到 0.678；
- 模糊长度达到 11 px 后，装甲板边缘和白色数字的高频信息被破坏，YOLO 漏检；
- 真实运动拖影长度近似满足 `模糊长度 ≈ 目标像速 × 曝光时间`，所以曝光时间越长、目标运动越快，越容易漏检；
- 真实运动实验需要在装甲板灯条修好后补拍。
